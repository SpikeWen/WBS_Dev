# 开发原则与代码规范

## 1. 目标

WBS 第一版是企业官网后台管理系统，不是一次性生成器。
代码和架构必须支持后续持续迭代，避免模块之间强耦合。

## 2. 设计原则

### 2.1 单向依赖

- UI 只调用应用层。
- 应用层只依赖领域模型和接口抽象。
- 基础设施层实现接口，不反向依赖业务逻辑。

### 2.2 低耦合

- 站点、内容、素材、发布、诊断分成独立模块。
- 模块之间通过明确的数据契约交互。
- 不在页面组件里直接写数据库逻辑。
- 不在业务服务里直接拼装前端展示文案。

### 2.3 高内聚

- 一个模块只负责一类职责。
- 站点信息归站点模块。
- 内容结构归内容模块。
- 发布流程归发布模块。

### 2.4 可替换

- 模板引擎可替换。
- 存储层可替换。
- LLM 调用可替换。
- AWA 联动可替换，且默认应为可选启用。

## 3. 代码风格

- TypeScript / Python 全部显式类型。
- 函数短小，优先单一职责。
- 业务常量集中管理。
- 禁止跨层直接 import 深层实现。
- 禁止在控制器里写复杂业务判断。
- 禁止在模板里拼接数据库字段逻辑。

## 4. 错误处理

- 接口层返回标准错误码和可读提示。
- 应用层抛出领域错误，不直接吞异常。
- 基础设施层负责包装第三方异常。
- 所有发布失败都要保留原因和上下文。

## 5. 日志与追踪

- 记录站点 id、内容 id、发布 id、任务 id。
- 记录操作人和时间。
- 记录生成前后的版本号。
- 记录 AWA 检测结果和建议，但不要把诊断逻辑写死在主发布链路里。

## 6. 版本管理

- 每次发布都要生成版本号。
- 内容修改只影响当前站点，不污染其他租户。
- 发布前的草稿、审核、上线状态必须分开。
