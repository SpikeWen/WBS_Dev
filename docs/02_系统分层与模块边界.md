# 系统分层与模块边界

## 1. 总体分层

```text
界面层
  -> 应用层
  -> 领域层
  -> 基础设施层
```

## 2. 界面层

职责：

- 接收用户操作。
- 展示站点状态。
- 渲染表单、列表、编辑器和预览页。
- 不包含复杂业务规则。

典型对象：

- 页面
- 表单
- 对话框
- 操作按钮

## 3. 应用层

职责：

- 协调站点创建、内容保存、预览、发布、回滚。
- 组合领域服务和基础设施接口。
- 管理事务边界。

典型对象：

- SiteApplicationService
- ContentApplicationService
- PublishApplicationService
- AuditApplicationService

## 4. 领域层

职责：

- 定义核心业务规则。
- 定义站点、页面、内容、素材、发布版本等实体。
- 定义约束和状态转换。

典型对象：

- Site
- Page
- ContentItem
- MediaAsset
- PublishVersion

## 5. 基础设施层

职责：

- 数据库读写。
- 文件存储。
- 模板渲染。
- LLM 调用。
- AWA 调用。

典型对象：

- Repository
- StorageAdapter
- TemplateRenderer
- LLMClient
- AWAClient

## 6. 模块边界

### 6.1 站点模块

负责：

- 站点创建
- 站点身份
- 域名配置
- 默认 SEO 配置

### 6.2 内容模块

负责：

- 固定页面
- 文章
- 产品
- 案例
- 服务
- FAQ

### 6.3 运营模块

负责：

- 展示位
- 轮播
- 外链
- 留言
- 内容关联链

### 6.4 工具模块

负责：

- 表单构建器
- 素材体检
- 媒体资产库
- 站内检索维护

### 6.5 发布模块

负责：

- 预览构建
- 正式发布
- 版本回滚
- sitemap 和 robots 生成

### 6.6 可见性模块

负责：

- 可选 AWA 调用
- 诊断结果回写
- 问题建议生成
- 诊断开关配置

## 7. 依赖方向

推荐依赖方向：

```text
界面层 -> 应用层 -> 领域层
基础设施层 -> 领域层接口
基础设施层 <- 应用层调用
```

禁止：

- 领域层依赖界面层。
- 领域层依赖数据库实现。
- 页面组件直接访问数据库。
- 发布模块直接修改别的模块内部状态。
