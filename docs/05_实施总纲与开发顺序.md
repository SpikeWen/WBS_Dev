# 实施总纲与开发顺序

## 1. 这份文档的作用

这是一份真正用于开工的实施文档，不是概念描述。

它的目标是把 WBS 第一版的开发顺序、目录边界、接口约定、页面范围、内容模型和发布流程固定下来，避免后续实现时方向漂移。

## 2. 第一版范围

### 2.1 必做

- 单租户或简化多租户站点创建。
- 固定模板站点骨架。
- 站点身份和企业档案维护。
- 页面树和内容项管理。
- 基础页面预览。
- 发布版本记录。
- sitemap 和 robots 输出。
- 图片和素材管理。

### 2.2 可选

- 可选 AWA 诊断接入。
- LLM 文案润色。
- 多模板切换。
- 站内搜索增强。

### 2.3 不做

- 复杂计费。
- 代理商体系。
- 多端小程序。
- 重型低代码拖拽编辑器。
- 复杂工作流引擎。

## 3. 推荐技术栈

### 3.1 前端

- React
- TypeScript
- Vite
- 组件库可选 shadcn/ui、Ant Design 或自研轻量组件

### 3.2 后端

- FastAPI
- Pydantic
- SQLAlchemy 或 SQLModel
- SQLite 起步，后续 MySQL/PostgreSQL
- Jinja2 用于静态模板或预览渲染

### 3.3 文件与任务

- 本地文件系统起步
- 后续 MinIO
- 简单后台任务队列起步

## 4. 推荐项目目录

```text
WBS_Dev/
  backend/
    app/
      api/
      application/
      domain/
      infrastructure/
      schemas/
      services/
      templates/
    tests/
  web/
    src/
      pages/
      components/
      modules/
      api/
      styles/
  docs/
  storage/
  exports/
  scripts/
```

### 4.1 backend/app/api

只放路由和请求响应层。

### 4.2 backend/app/application

放站点、内容、发布、素材、诊断等应用服务。

### 4.3 backend/app/domain

放领域实体、值对象、规则、状态转换。

### 4.4 backend/app/infrastructure

放数据库、文件、模板渲染、外部服务适配器。

### 4.5 web/src/modules

按业务域拆模块，而不是按页面零散堆代码。

建议模块：

- dashboard
- site
- profile
- content
- media
- publish
- diagnostic

## 5. 数据主线

站点的核心数据流应固定为：

```text
站点创建
  -> 站点身份
  -> 企业档案
  -> 页面树
  -> 内容条目
  -> 媒体资产
  -> 预览构建
  -> 发布版本
  -> 前台展示
```

任何新能力都要挂到这条主线上，不要单独开一条平行的数据链。

## 6. 后端接口草案

### 6.1 站点

- `POST /api/sites`
- `GET /api/sites/{site_id}`
- `PATCH /api/sites/{site_id}`
- `GET /api/sites/{site_id}/status`

### 6.2 企业档案

- `GET /api/sites/{site_id}/profile`
- `PUT /api/sites/{site_id}/profile`

### 6.3 页面树

- `GET /api/sites/{site_id}/pages`
- `POST /api/sites/{site_id}/pages`
- `PATCH /api/pages/{page_id}`
- `DELETE /api/pages/{page_id}`

### 6.4 内容项

- `GET /api/sites/{site_id}/contents`
- `POST /api/sites/{site_id}/contents`
- `PATCH /api/contents/{content_id}`
- `POST /api/contents/{content_id}/publish`
- `POST /api/contents/{content_id}/unpublish`

### 6.5 素材

- `GET /api/sites/{site_id}/assets`
- `POST /api/sites/{site_id}/assets`
- `PATCH /api/assets/{asset_id}`
- `DELETE /api/assets/{asset_id}`

### 6.6 发布

- `POST /api/sites/{site_id}/preview`
- `POST /api/sites/{site_id}/publish`
- `POST /api/sites/{site_id}/rollback`
- `GET /api/sites/{site_id}/publishes`

### 6.7 可选诊断

- `POST /api/sites/{site_id}/diagnostic/run`
- `GET /api/sites/{site_id}/diagnostic/latest`

## 7. 前端页面草案

### 7.1 站点驾驶舱

目的：

- 显示站点状态。
- 显示待补内容。
- 显示最近发布。
- 显示最新可选诊断结果。

### 7.2 站点配置页

目的：

- 维护站点信息。
- 维护企业档案。
- 维护 SEO 默认项。

### 7.3 页面树页

目的：

- 管理导航和页面结构。
- 创建固定页面、列表页、详情页。

### 7.4 内容编辑页

目的：

- 编辑文章、产品、案例、FAQ 等。
- 绑定素材和 SEO 信息。

### 7.5 媒体资产页

目的：

- 上传图片、文档、证书。
- 填写 alt。
- 查看使用情况。

### 7.6 发布页

目的：

- 预览站点。
- 触发发布。
- 查看版本历史。

### 7.7 可选诊断页

目的：

- 如果用户启用 AWA，可查看抓取、可读性和结构化信号建议。

## 9. 发布流程

```text
内容保存
  -> 校验字段
  -> 生成预览
  -> 用户检查
  -> 创建发布版本
  -> 生成静态结果
  -> 输出 sitemap / robots
  -> 切换线上版本
```

### 9.1 发布前校验

- 基础字段是否完整。
- 页面是否有 Title、H1、Meta。
- 图片是否有 alt。
- 重要页面是否可访问。
- 站点是否存在空内容。

### 9.2 发布后记录

- 发布人。
- 发布时间。
- 发布版本号。
- 生成文件路径。
- 失败原因（如有）。

## 10. 开发顺序

### 第一步

- 搭项目骨架。
- 建目录。
- 建基础配置。
- 建站点实体。

### 第二步

- 做站点驾驶舱。
- 做站点身份和企业档案页。

### 第三步

- 做页面树。
- 做固定页面和内容编辑页。

### 第四步

- 做媒体资产库。
- 做预览渲染。

### 第五步

- 做发布版本和静态输出。
- 做 sitemap / robots。

### 第六步

- 再考虑可选诊断接入。

## 11. 验收条件

第一版的最低验收标准：

- 能新建一个站点。
- 能配置站点信息。
- 能维护至少 4 类内容。
- 能生成可访问预览页。
- 能发布站点版本。
- 能导出基础 SEO 结果。
- 可选诊断功能不影响主链路。

## 12. 实施提醒

- 不要先写复杂插件系统。
- 不要先做多租户计费。
- 不要先做拖拽式页面搭建器。
- 不要把 AWA 放进主流程硬门禁。
- 不要让 UI 直接操纵底层数据文件。
